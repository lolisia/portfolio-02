# 모바일 웹 성능 검증 — 2026-11-17

USB 디버깅으로 연결한 실제 Android Chrome에서 Forest Farm 웹 버전을 측정했다.
기존 버전은 기본 낮 약 44 FPS, 야간 약 37 FPS, 눈보라 약 31 FPS였다.
최종 배포 빌드는 카메라 회전·비·확대 및 야간 눈보라 연속 실행에서 약 60 FPS를 유지했다.

## 기기와 측정 조건

- 기기 모델: `2511FPC34G`, GPU: `ANGLE (ARM, Mali-G720 MC8, OpenGL ES 3.2)`.
- Chrome `157.0.8103.51`, 세로 화면 CSS `390×728`, 기기 DPR `3.25`.
- 실제 3D 캔버스는 변경 전후 모두 `390×728`. 메인 화면 해상도를 추가로 낮추지 않았다.
- USB ADB reverse와 Chrome DevTools Protocol로 실행·측정했다. 기기의 외부 도메인 DNS 조회가 실패해 로컬에서 같은 정적 배포 파일을 제공했다.
- 로딩과 최소 60프레임 및 추가 5초를 기다린 후, 화면이 visible인 상태에서 측정했다. 측정 중 화면 wake lock을 사용했다.
- FPS는 애니메이션 콜백 간격의 평균, P95는 그 간격의 95백분위다. draw call/삼각형은 후처리·반사까지 전체 패스를 합산했다.
- GPU timer extension은 지원되지 않아 GPU 밀리초 수치를 주장하지 않는다. 별도로 SurfaceFlinger의 실제 표시 타임스탬프를 대조했다.

## 결과

기준 버전은 `7774cd3`의 웹 빌드/소스다. 개발 서버 결과와 정적 배포 빌드 결과를 구분한다.
장면의 동물·입자는 계속 움직이며, 측정 순서·발열을 완전히 통제한 벤치마크는 아니다.

|---|---:|---:|---:|---|
| 기본 낮 | 43.96 | 60.35 | 16.7 ms | 개발 서버, 30초 |
| 기본 야간 | 37.10 | 60.35 | 16.7 ms | 개발 서버, 30초 |
| 낮 눈보라·겨울 | 31.24 | 60.35 | 16.7 ms | 개발 서버, 30초 |
| 비 | 38.22 | 60.35 | 16.7 ms | 정적 배포 빌드, 35초 |

| 반복 터치 드래그로 카메라 회전 | — | 60.30 | 16.7 ms | 정적 배포 빌드, 약 21초 |

연속 실행은 7,243프레임을 기록했고 최대 콜백 간격도 16.7 ms였다.
페이지 오류와 WebGL context lost/restored 이벤트는 모두 0개였다.
동일 장면을 유지한 상태의 SurfaceFlinger 표시는 약 20.28초 동안 1,225프레임,
평균 **60.35 FPS**, P95 **16.67 ms**, 최대 **16.85 ms**였다.
연속 실행 후 Android thermal status는 0, 배터리 온도는 약 38.3°C였다.

최종 코드 `188e082`를 `https://aisilol.com/diorama/`에 반영했다.
HTML·JS·CSS 응답을 시험한 정적 빌드와 바이트 단위로 비교했고 모델 두 파일의 200 응답도 확인했다.
이후 기기의 DNS가 정상 동작해 USB 로컬 서버를 거치지 않는 공개 HTTPS URL에서도
30초간 1,811프레임, 평균 60.35 FPS를 확인했다. 기존 nginx 설정을 그대로 사용했다.

비 장면의 첫 개발 서버 측정은 58.82 FPS였고 497 ms를 포함한 몇 개의 긴 프레임이 있었다.
반복 개발 재로딩 중 Chrome GPU 프로세스가 재시작되어 다음 로딩의 컨텍스트 생성도 실패했다.
이 실패를 성공 측정에 포함하지 않았으며, GPU 복구 후 정적 배포 빌드로 다시 검증했다.
위의 비·회전·확대 및 2분 연속 실행은 복구 후 결과다.

원시 프레임 JSON, 기기 스크린샷, SurfaceFlinger 타임스탬프 및 온도 기록은
로컬 `.artifact/mobile-web/`에 있다. 파일 이름은 `baseline-*`, `optimized-*-r2`,
`release-rain`, `release-closeup`, `release-orbit`, `release-soak`, `surfaceflinger-soak`이다.

## 변경과 화질

- `mobile-quality.js`: 작은 화면과 coarse pointer에서 모바일 프로필 선택.
  `?quality=desktop` / `?quality=mobile`로 같은 기기에서 비교할 수 있다.
- 잔디의 **모든 패치 위치와 패치당 12개 풀잎 유지**. 실제 GLB의 연결 관계와 UV를 검증한 뒤,
  패치당 96→36정점, 48→12삼각형으로 단순화한다. 뿌리 중심과 끝 위치·높이를 보존하고
  폭을 1.3배로 보완한다. 총 삼각형 면적은 원본의 ±10% 이내다. 알 수 없는 에셋 구조는 원본을 사용한다.
- 잔디 눌림 슬롯 16→4. 바람 애니메이션과 캐릭터 주변 반응은 유지한다.
- 연못 반사 640×512→320×256, 약 30 Hz로 캐시한다. 카메라·줌·투영 변화 때 즉시 갱신하며
  메인 수면의 물결은 매 프레임 움직인다. 반사 화면에서 식물·집·캐릭터를 제거하지 않았다.
- 안개 해상도 0.5→0.33, 적분 단계 24→16. 위/아래 구간의 총 적분 길이를 유지한다.
- AO는 기존 반해상도·8샘플을 유지하고 안개와 별도 그리드에서 깊이 보정 복원한다.
- 태양 그림자 2048, bloom, 색 보정, 주요 나무·집·캐릭터·폭포 형상은 유지한다.
- 모바일 눈 최대 9,000→2,500개, 크기 1.25배. 비 1,600→1,200개, 빗물 튐 300→100개.
  폭포 물방울 900→300개, 미세 안개 24→12개. 눈보라/일반 눈과 폭포 낙하/충돌 입자의 비율은 유지한다.
- 결빙되지 않은 물에서는 결과에 기여하지 않는 얼음 균열 계산을 건너뛴다.
- 데스크톱은 기존 형상·반사·안개·입자 설정을 유지한다.

실기기 낮·야간·눈보라와 정원 확대 화면을 전후 비교했다.
기본 작은 화면에서는 주요 형상과 분위기를 유지한다. 크게 확대하면 풀잎의 굽은 형상이
더 단순한 삼각형으로 보이며, 눈·미세 물방울의 수는 줄어든다. 픽셀 단위 동일 화질을 의미하지 않는다.

## 재검증

Git Bash에서:

```bash
VERIFY_SKIP_GODOT=1 bash scripts/verify.sh
npm run build:diorama -- --outDir .artifact/mobile-production/diorama
```

`tools/mobile-web-quality-test.mjs`는 실제 GLB 3종의 풀잎 뿌리·끝점·면적 보존,
원본 불변, 알 수 없는 구조의 fallback 및 프로필 선택을 확인한다.
데스크톱 Chrome에서 정적 빌드의 두 모델 로딩·환경 패널 동작과 페이지 오류 부재도 확인했다.
별도 진행 중인 Godot 변경은 수정·커밋하거나 실행 검증하지 않았다.

이 결과는 위의 연결 기기와 시험 장면에 대한 검증이다. 다른 GPU·브라우저·전원 절약 상태까지
60 FPS를 보장하지는 않는다.
