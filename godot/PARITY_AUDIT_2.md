## A. 사용자 보고 항목 (원인 확인 완료)

### A1. 캐릭터가 집 앞에 끼어 이동하지 못함 — P0

**재현**: 08:30 시작 → 6초에 문을 열고 나옴 → `exiting` 상태로 문 앞 `(-1.00, -0.60)`에서 40초 이상 정지 → 귀가 상태로 바뀌어도 같은 자리에서 움직이지 않음.

**원인**
1. **배치용 원을 충돌체로 사용.** 웹은 배치 판정(`occupy`/`free`, 나무·꽃 안 겹치게 하는 용도)과 충돌(`colliders.box/circle`)을 분리함. Godot `resolve_body()`는 배치용 `obstacles` 중 반경 1.3 미만 원을 모두 밀어내기에 사용함. 포치 계단 위에 깔린 배치용 원 `(-1, 0.35, r=0.75)`이 계단 전체를 덮어서, 문 앞 `z=-0.59`로 한 걸음 나가는 순간 `-0.60`으로 되밀림.
   - 같은 이유로 계단 위 점 `(-1,0.6)`, `(-1,0.9)`은 `(-1,1.3)`으로 튕겨 나감. 귀가할 때는 계단 아래 `z=1.3`에서 더 올라가지 못함.
2. **apron이 서 있을 수 없는 점.** `cottage_apron=(-1, 1.05)`인데 `is_on_porch` 범위는 `z<0.97`까지라 포치로 인정되지 않고, `is_free_for_walker()`도 같은 배치용 원(0.75+0.16) 때문에 거부함. 경로의 최종 목적지가 갈 수 없는 점임.
3. **막힘 탈출 없음.** 웹 `walk()`는 실제 이동량이 목표의 30% 미만인 상태가 1.2초 지속되면 그 경유지를 버림(`s.stuck`). Godot은 `resolve_body`가 제자리로 되돌려도 `moved=true`로 처리해 같은 경유지를 영원히 시도함.
4. 경로 그래프도 배치용 원(반경 ≥0.55: 농가 2.3, 정원 화단 0.8, 큰 나무 0.58·s)으로 걸을 수 있는 곳을 판정함. 웹 `walkable`은 충돌체(나무 0.32·s, 건물·난간 박스)만 봄 → Godot 그래프 노드 분포가 웹과 다름.

**수정 방향**: `resolve_body`·`is_free_for_walker`·`walkable`에서 배치용 `obstacles`를 빼고 웹 `createColliders()`와 같은 충돌체(박스 + 나무 0.32·s, 덤불·그루터기 `plant`, 램프 0.2 원, 울타리 박스)만 사용. `_walk_route`에 웹 `stuck` 타이머 이식. 포치 체인 수동 노드는 충돌체가 웹과 같아지면 불필요.

**그 밖의 패널 디테일**
- 체크박스: 웹은 12px 흰 accent 체크박스, Godot은 어두운 채운 사각형.

- 패널 가장자리 굴절: 웹은 베벨 16px에서 최대 8px 이동. Godot은 왼쪽 가장자리에서 장면이 길게 번져 보임(1280×720 패널 캡처).
- 접기 아이콘: 웹은 테두리 2개로 만든 꺾쇠가 0.25초 회전. Godot은 `˄/˅` 글자.

### A3. 겨울 전환 시 일부 나무 잎이 한 번에 사라짐 — P0

**원인**: `foliage.gdshader`
```glsl
if (evergreen < 0.5 && winter > 0.5 && hash(v_origin.xz) < winter * 0.95) discard;
```
- `winter > 0.5` 조건 때문에 winter가 0.5를 넘는 **한 프레임에 hash < 0.475인 모든 인스턴스(나무·덤불·풀의 약 절반)가 동시에 사라짐**. 그 뒤 나머지만 점진적으로 사라짐.
- 웹은 `plantRank < winterBare`(조건 없음)라 winterBare가 0→1로 오르는 동안(1.6 속도, 약 2~3초) 인스턴스가 고르게 하나씩 사라짐.
- `* 0.95` 때문에 한겨울에도 약 5%의 활엽수·덤불·풀이 초록 잎을 유지함(`--winter` 캡처에서 오른쪽 참나무와 농가 옆 덤불이 초록). 웹은 winterBare=1에서 전부 사라짐.

**수정**: `if (evergreen < 0.5 && rank < winter) discard;`. rank는 웹처럼 인스턴스 위치 해시 `fract(dot(origin, vec3(16.321, 28.735, 9.135)))`.

> 참고: 웹도 나무 단위로 잎 전체가 한 번에 사라지는 방식임(나무 하나 = 인스턴스 하나). 나무 하나하나의 잎이 서서히 줄어드는 연출을 원하면 잎 카드 단위 rank를 쓰는 개선이 필요하며, 이 경우 웹과도 달라짐. 결정 필요.

### A4. 마우스 드래그 상하 방향이 반대 — P0

**원인**: 1차 수정에서 `pitch`를 극각에서 **고도각**으로 바꿨는데 드래그 부호는 그대로 둠.
- 웹 OrbitControls: 아래로 드래그(dy>0) → `phi -= angle` → 극각 감소 → 카메라가 **위로** 올라가 더 내려다봄.
- Godot `orbit_camera.gd`: `pitch_target -= relative.y * …` → 고도 감소 → 카메라가 **아래로** 내려감.
- 마우스(89행)와 터치 드래그(104행) 모두 `+=`로 바꿔야 함. 좌우(yaw)는 웹과 같음.

### A5. 잔디·나뭇잎이 너무 진한 녹색 — P1

**측정**: 기본 화면 섬 영역의 녹색 픽셀 평균 — 웹 `(92, 102, 72)` 올리브빛 / Godot `(96, 113, 96)` 푸르고 차가운 녹색. 밝기는 비슷하지만 Godot은 노란기가 빠지고 파란 성분이 높음.

**원인 (영향 큰 순)**
1. **하늘·배경 색 이중 sRGB 변환**: `day_cycle.gd`가 `srgb_to_linear()`한 값을 `source_color` 힌트가 붙은 uniform(`sky.gdshader`의 `sky_top/horizon/land`, `backdrop.gdshader`의 `bg_top/bg_bottom`)에 넣음. Godot은 `source_color` uniform에 넣은 색을 다시 선형으로 바꾸므로 **두 번 변환되어 어둡고 채도가 높은 파랑**이 됨. 이 하늘이 앰비언트·반사 광원이라 잎과 풀에 푸른 기가 섞임(배경 문제는 B1 참고).
2. **지형 바탕색이 어두움**: 웹 지면 캔버스 평균 RGB `(123,149,73)`/255 ≈ `(0.48, 0.58, 0.29)`에 밝은 반점(`#cad57377`)이 섞임. Godot `_terrain_color`는 `(0.20,0.29,0.13)~(0.40,0.48,0.20)`으로 평균 약 25% 어두움. 풀 사이로 보이는 땅이 진한 녹색으로 보임.
3. **웹에 없는 명암 추가**: `nature_assets.gd`가 정점색을 `0.82 + 0.10·normal.y + 0.08·height`로 합성함. 웹 nature 메시는 정점색이 없어 흰색(1.0)이 쓰임 → Godot이 최대 18% 더 어두움. foliage 셰이더의 dapple(`0.82 + 0.28·leaf + 0.08·fine`)도 웹에 없음.
4. **잎 텍스처 색 누락**: 웹 잎은 `spray` 텍스처(잎 색 `#dce4be/#d1d9ac/#f0edc7/#bac791`, 줄기 `#78774d`)를 인스턴스 색에 곱해 노랗고 연한 올리브가 됨. Godot은 텍스처 없이 인스턴스 색만 사용 → 채도 높은 녹색.
5. 안개 중첩(B2)이 화면 중앙에 푸른 흰 막을 씌워 대비가 바뀜.

### A6. 침엽수 잎이 체크무늬처럼 보임 — P1

**원인**: `needle_mask()`가 **월드 좌표 XZ 격자**(`fract(p.xz*18 + …)`)로 바늘을 잘라냄. 메시 방향과 무관한 화면 고정 격자라 위에서 보면 점이 줄지어 박힌 체크무늬가 됨. 활엽수 `broadleaf_mask()`도 같은 방식이라 잎 가장자리가 픽셀 노이즈처럼 보임(`--garden` 캡처 상단 소나무, 기본 화면 나무들).

**웹**: nature.glb 잎 카드의 **메시 UV**로 `leafSpray()` 256² 캔버스(가지 + 피침형 잎 / 침엽 15쌍)를 샘플링하고 `alphaTest 0.29`, 양면 렌더.

**수정 방향**: `foliage.js::leafSpray(needles)`를 GDScript `Image`로 그려(또는 PNG로 구워) `ALBEDO_TEXTURE`로 쓰고, `UV`로 샘플링 + `ALPHA_SCISSOR_THRESHOLD = 0.29`. 텍스처 색까지 곱하면 A5-4도 함께 해결됨.

## B. 추가로 발견한 불일치

### B1. 배경 하늘 색 — P1
- 측정(왼쪽 위 / 왼쪽 가운데 / 오른쪽 아래): 웹 `(171,189,201) / (189,200,202) / (199,205,203)` 연한 회청색. Godot `(92,135,163) / (135,162,170) / (158,172,168)` 진한 파랑.
- 원인: A5-1과 같은 이중 sRGB 변환.
- 밤: 웹은 남색 하늘(`#17263f` 계열)이라 섬과 오두막, 연기가 보임. Godot은 거의 검정이라 섬 윤곽이 잘 안 보임(`--night`). 같은 원인으로 어두운 색이 더 크게 깎임.

### B2. 안개가 4겹으로 쌓임 — P1
- 웹: 하프 해상도 레이마칭 안개 1개(`mist.js`)만 있음.
- Godot: Environment 깊이 안개(`fog_density`) + 볼류메트릭 안개(30%) + `ForestMist` FogVolume(22%) + CompositorEffect 레이마칭이 **모두 켜져 있음**. 낮 기본 화면에서 섬 가운데에 흰 막이 끼고(`--coop`, `--garden`, 기본 화면), 근경이 뿌옇게 보임.
- 수정: CompositorEffect가 동작할 때는 나머지 3개를 끄고, Mobile/Low 폴백에서만 사용.

### B3. 폭포 — P1
| 항목 | 웹 (`?view=falls`) | Godot (`--falls`) |
|---|---|---|
| 커튼 | 반투명 청록 물막에 밝은 줄무늬·거품이 섞이고, 아래로 갈수록 바깥으로 휘며 물보라로 흩어짐 | 거의 불투명한 흰 판, 굵은 줄 2개, 수직으로 떨어짐 |
| 바닥 | 넓고 납작한 바위 위에 거품 원판 | 작은 바위 1개 + 벽 밖에 떠 있는 바위 1개 |
| 입구 바위 | 양쪽 가장자리 바위 2개씩이 보임 | 잘 보이지 않음 |
| 이상 현상 | 없음 | 연못 왼쪽에서 벽 아래까지 **흰 점이 세로 한 줄로 늘어선 기둥**이 보임(출처 미확인, 확인 필요) |

### B4. 경계 벽 질감 — P1
- 웹: 기둥마다 흙층 1 + 암석 4층이 **뚜렷한 색 띠**(`#474f54`→`#737771`)와 0.25 단위 계단 모양으로 보이고, stone 텍스처(얼룩·이끼)는 은은함.
- Godot: 표면 셰이더의 절벽 지층·균열(`strata`, `bedding`, `crack`, 웹에 없음)과 강한 노멀 요철 때문에 전체가 어두운 자갈 질감으로 보이고 4개 색 띠가 구분되지 않음. 흙층도 웹보다 얇고 거칠어 보임.

### B5. 지붕 재질 — P1
- 웹 clay(지붕널·기와): 알베도는 회색 183~253 범위의 은은한 얼룩, 노멀 깊이 0.85.
- Godot: `cos(p.x·2π·0.7)²` 줄무늬 진폭과 노멀 섭동이 커서 **농가 지붕널과 닭장 기와가 벽돌 쌓기 무늬처럼 보임**(`--coop`, `--garden`).

### B6. 겨울 나무 — P1
- 소나무: 웹은 눈 덮인 빽빽한 원뿔. Godot은 A6의 격자 컷 때문에 하얀 점박이 덩어리.
- 맨 나무 줄기: 웹은 진한 갈색 줄기와 가는 가지. Godot은 굵고 회녹색으로 보임(눈 덮임 + bark 색 확인 필요).
- 일부 활엽수·덤불이 초록 잎을 유지(A3의 0.95).

### B7. 개발용 카메라 프리셋 — P2
- `--garden`, `--coop`이 웹 `?view=garden|coop`(오프셋 `(24,18,30)` 방향, 위에서 내려다봄)과 달리 낮은 각도에서 하늘이 보이는 정면 시점임. 비교 캡처가 어긋나므로 웹 close-up 공식(`target + rotateY((24,18,30), yaw)`, zoom)으로 다시 계산 필요.

### B8. 캐릭터 경로 그래프 — P1
- A1-4 참고. 웹 `walkable=!colliders.blocked(x,z,.26) && wet<-.2`. Godot은 배치용 원 기준이라 큰 나무 주변(0.58·s+0.16)과 정원 화단 원(0.8)이 넓게 막혀 산책 목적지 후보가 웹보다 적고, 포치는 수동 체인으로만 연결됨.

## 권장 수정 순서

1. **A4 드래그 방향**, **A3 겨울 잎 discard**: 한두 줄 수정.
2. **A1 캐릭터 충돌**: 배치용 원과 충돌체 분리 + stuck 타이머. 이후 B8 그래프가 자동으로 맞춰짐.

8. **B7 프리셋** 재계산 후 전체 화면을 다시 캡처해 비교.
